# 跨国展览成果释出协调

本仓库维护中埃联合考古成果释出协调服务的领域事件实现：把发掘单元、文物对象、原始记录、解释主张、贡献人、翻译稿、借展条款、禁发期与公开载体（展签、图录、公共讲座、学术论文）连成可追踪关系。仅使用 Python 标准库，事件以 JSONL 落盘，进程重启后靠重放恢复。

## 目录

- `contracts/domain.schema.json`：领域对象与事件名称约定。
- `data/sample.json`：一条可用于本地联调的示例事件。
- `src/envelope.py`：事件信封的基础字段校验。
- `src/events.py`：事件/聚合/载体/参与方常量与事件构造、内容指纹。
- `src/store.py`：仅追加事件存储（乐观锁、崩溃后重放）。
- `src/model.py`：事件流 → 当前世界状态的纯函数折叠。
- `src/service.py`：成果释出协调服务，全部业务规则的唯一裁决处。
- `src/trace.py`：从一句展签回溯数据、翻译、许可、署名与当时结论。
- `src/cli.py`：事件校验与溯源查询命令入口。
- `tests/`：信封回归测试与端到端场景测试。

## 领域规则

- **冻结引用版本**：提交释出方案时，原始记录、解释主张、翻译稿等引用按版本冻结，快照随 `RELEASE_REQUESTED` 事件持久化；日后记录勘误不影响已发布内容所依据的数据。
- **中埃双边会签**：CN、EG 两方数据责任人分别确认，两边到齐才批准；同一方换人重复会签被拒，本人重试幂等；存储层乐观锁保证并发批准不能越过双边确认。
- **编辑受批准范围约束**：策展编辑只能对已批准申请、在批准载体与借展条款允许范围内生成公众版本。
- **相同重试复用，变化新建版本**：申请内容（载体、引用版本、贡献人）规范化后取指纹；相同内容的重试（含客户端换编号）回到原流程且不产生事件；内容变化必须以 `revision_of` 新建申请版本。
- **局部撤展**：文物临时撤展只暂停依赖实体展示的载体（展签），学术论文等已获准学术事实不被自动封锁；返展时自动恢复，但禁发期未过或借展不允许时保持暂停。
- **更正不覆盖**：解释主张修订与公众版本更正都产生新版本并与旧版关联（`correction_of` / `corrected_by`），曾经展出的内容原样保留；同一条展签键始终指向当前最新版。
- **独立待办**：贡献人异议、翻译争议各自开立独立争议与待办；禁发期延期单独开立待办，批准才生效，驳回保持原期限。
- **初步结论标注不确定性**：主张带 `provisional` / `confirmed` 确定性标注，溯源时展示发布当时的标注与后续更正。
- **恢复后继续会签**：`recover_pending_decisions` 补偿“双边会签已落盘但批准事件未及写入”的中断，且幂等。

事件标识一旦接收不得原地复用为另一份内容，版本必须为正整数且按聚合连续递增，时间采用带时区的 ISO 8601 格式。业务修订通过新事件表达，原始记录继续用于追溯。

## 本地运行

检查示例事件：

```bash
python3 -m src.cli data/sample.json
```

对事件存储中的一条展签做溯源查询：

```bash
python3 -m src.cli trace events.jsonl gallery_label obj-005-intro
```

运行测试：

```bash
python3 -m unittest discover -s tests
```

编译检查：

```bash
python3 -m compileall -q src tests
```

## 场景测试覆盖

`tests/test_scenarios.py` 端到端验证：局部撤展只暂停实体载体、禁发延期在新期限前阻断、异议与翻译争议各自独立待办与解决、已发布内容经更正关联新版而不被覆盖、相同申请重试复用/内容变化新建版本、并发会签无法越过双边确认、崩溃恢复后完成未竟会签，以及从一句展签追到冻结数据、翻译稿、借展与双边许可、贡献署名和当时有效的研究结论。
